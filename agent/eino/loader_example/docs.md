# Document Loader

接下来的内容是和rag相关的内容

如果你要准备一个知识库，思考一下准备流程是什么

准备数据，检索数据，使用数据

用户问题 + 知识库资料 ---> llm ---> 回答

面临痛点：真实业务场景中面临的资料或知识库多达几万多条，大模型的上下文是有限度的，就算有超长上下文，其注意力也是有限度的，基于这种现状，如何从工程方面完善这种能力？

用户的问题+跟问题相关的知识 ——> llm ——> 回答

rag由此产生

准备数据 ——> 检索数据 ——> 使用数据

Loader ----> transformer（拆分数据） ----> embedding ----> indexer (存储)----> retriever（查询）
